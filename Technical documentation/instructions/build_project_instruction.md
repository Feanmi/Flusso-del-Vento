# Руководство по сборке проекта STM32 с использованием STM32CubeMX и STM32CubeIDE

## Предварительные требования

### Установленное ПО:
1. **STM32CubeMX** (версия 6.10 или выше) (рекомендуется 6.16) [link](https://www.st.com/en/development-tools/stm32cubeide.html)
2. **STM32CubeIDE** (версия 1.17 или выше) (рекомендуется 2.0) [link](https://www.st.com/en/development-tools/stm32cubemx.html)
3. **Java Runtime Environment** (требуется для CubeMX) (должен быть уже установлен)

### Дополнительно:
- Актуальные пакеты STM32Cube для серии МК (L1) 
    - устанавливаются через cubemx; в разделе **Help->Manage embedded software packages** найти серию МК **STM32L1** и скачать самый первый файл
    - если проблемы с proxy или другие проблемы не дают скачать, обратиться к [@sermerl2](https://t.me/@sermerL2) за пакетом
- USB-драйверы для программатора/отладчика (ST-Link, J-Link и т.д.) (найдите сами пж)

## Примечание 1. Структура проекта

```
Типичная структура в Project Explorer:
   MyProject/
     ├── Core/
     │   ├── Inc/     // Заголовочные файлы
     │   ├── Src/     // Исходные файлы
     │   └── Startup/ // Стартап файлы
     ├── Drivers/
     │   ├── CMSIS/   // Cortex Microcontroller Software Interface Standard
     │   └── STM32F4xx_HAL_Driver/
     └── MyProject.ioc // Конфигурационный файл CubeMX
```

Для нас основными являются 2 директории **[/Core](#core)** и **[/Drivers](#drivers)**

### /Core

Директория содержит 3 поддиректории:
- **/Startup** директория с ассемблерным кодомм запуска МК **не менять!**
- **/Src** директория с файлами исходников
    - в директории находятся файлы переферии МК и основной main.c
        - изменения в main.c производить только с согласованием с [Максимом Поповым](https://t.me/@maxim_magnum_invocabunt)
    - также существует нужная вам поддиректория **/modules**
        - в ней находятся созданные вами исходники на **C**
- **/Inc** имеет аналогичную структуру с **/Src**, но хранит заголовочные файлы

### /Drivers

В проектах STM32CubeIDE директория **/Drivers** содержит низкоуровневые драйверы для работы с железом микроконтроллера STM32.
В нашем проекте там находятся драйвера CMSIS и HAL

```
CMSIS — это стандартизированный низкоуровневый интерфейс для процессоров ARM Cortex-M
HAL — это абстракция над периферией STM32, предоставляющая унифицированные функции для управления конкретными модулями микроконтроллера.
```

## Шаг 3: Добавление вашего кода

В CubeIDE расскройте дерево проекта до уровней **/modules** директорий **/Inc** и **/Src**
При помощи ПКМ добавте новый файл в **/modules** директорий **/Inc** и **/Src** (**.h** и **.c** соответственно)
Добавьте исходный код в только что созданный файл **.c**
Реализуйте заголовочный файл **.h** по следующему примеру:

```C
#ifndef DISTANCE_MEAS_H
#define DISTANCE_MEAS_H

// подключение стандартных библиотек C
#include "common.h" 

// подключение библиотек переферии МК
#include "gpio.h"
#include "i2c.h"

// подключение иных файлов/библиотек
#include "vl53l0x_api.h"

// объявления функций
void init_ranging_sensor();
void read_distance();

#endif //DISTANCE_MEAS_H
```

В случае отсутствия вашего кода ранее, подключите заголовочный файл в **main.c** (разрешается делать самостоятельно)

Если требуется изменить настройуи переферии МК, перейдите к [примечанию 2](#примечание-2-изменение-настроек-переферии)
Если требуется добавить драйвера, обратитесь к [примечанию 3](#примечание-3-добавление-драйвера)

## Примечание 2. Изменение настроек переферии

Для изменения настроек переферии предпочтительней вносить изменения в проект **CubeMX** (файл .ioc)
- это связано с тем, что обновленные параметры в коде будут перезаписаны, если кто-то другой перегенерит проект
- также **CubeMX** не позволит вам выставить недопустимые значения

При правке .ioc файла следуйте следующим правилам:
- **НЕ МЕНЯТЬ НАСТРОЕК ПИТАНИЯ RCC**
- **НЕ МЕНЯТЬ НАСТРОЕК ТАКТИРОВАНИЯ**
- **НЕ МЕНЯТЬ ПЕРЕФЕРИЙНЫЕ МОДУЛИ, НЕ СВЯЗАННЫЕ С ВАШЕЙ ФУНКЦИЕЙ**
- **Разрешается использование "пустых" GPIO**
- **Разрешается менять ваш переферийный модуль как угодно, если изменения никак не влияют на другие функции МК и ПО**

После внесения изменений напрвьтесь во вкладку **Project Manager**, проверьте наличие пакета cubemx для МК L1 (если нет, то перейлите к [дополнительно](#дополнительно)), нажмите **GENERATE CODE**, после окончания нажмите close и закройте **CubeMX**. Перед открытием проекта удвлите старый из workspace, нажав **ПКМ** на проект в дереве проекта, далее нажмите **Delete**. Далее импортируйте проект в workspace также, как и во [2-м шаге](#шаг-2-собрать-существующий-проект)

## Примечание 3. Добавление драйвера

Если вам надо добваить драйвер, рекомендуется добавлять папку через **Проводник ОС**. После обновления нажмите **Refresh** в проекте и папка появиться в дереве проекта.

Далее следует добавить директории **/Inc** в **Include paths** компилятора
- в самой верхней панели выберете **Project->Properties**
- далее  перейдите в **С/C++ Buld->Settings->MCU/MPU GCC Compiler->Include paths**
- в раздел **Include paths** вставьте пути до **/inc** Пример: ``` "${workspace_loc:/${ProjName}/Drivers/VL53L0X/core/inc}" ```
- нажать **Apply**
- если попросят перестроить индексы, тыкайте че хотите, я так и не понял что это значит))))
- проверить работоспособность, собрав проект

## Шаг 4: Сборка, загрузка на МК, отладка

- Сохраните все файлы
- Нажамите кнопку **Build** в панеле инструментов или кликнув **ПКМ** по проекту в дереве проекта
- Проверить на наличие ошибок
    - если есть ошибки в файлах других модулей, сообщите авторам о них
    - если не собирается проект из-за ошибок компилятора (к примеру не найдены стандартные библиотеки и т.п.) воспользуйтесь интернетом или обратитесь к [@sermerl2](https://t.me/@sermerL2)
    - если ошибок нет, можете приступать к интеграции своих модулей
- Подключите МК к питанию по гайду в ТГ от Евгения Анатольевича
- Подключите МК по USB к ПК
- Проверьте, что драйвера подтянулись и МК определился
- Нажмите кнопку **Run** в панеле инструментов или кликнув **ПКМ** по проекту в дереве проекта
- Далее тестируйте разработанную вами часть (для этого видимо будет другое руководство)
- Для запуска МК в режиме отладки нажамите кнопку **Debug** в панеле инструментов или кликнув **Debug** по проекту в дереве проекта
